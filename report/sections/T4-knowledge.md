## 对操作系统的理解

**负责人：** 2414099－李云鹏（lyp）

Lab1 的内核只做启动栈建立、BSS 初始化和加载提示输出，随后停在无限循环。它展示了运行内核之前必须具备的执行条件，也给后续内存管理、异常处理和进程管理留下了入口。以下按当前代码与 T1/T2/T3 的验证结果对照原理概念。

### 1. 本实验的重要知识点与 OS 原理的对应

| 实验知识点与事实 | 对应的 OS 原理概念及含义 | 联系与差异 |
|---|---|---|
| QEMU 的复位代码 → OpenSBI → `kern_entry` → `kern_init` | 系统引导：逐步准备硬件和软件执行环境，再交给操作系统入口 | 实验把阶段交接具体化为 PC、寄存器和特权级变化。当前模拟器在 CPU 执行前装载 ELF，没有实现从磁盘读内核的通用 bootloader；不能把 OpenSBI 直接等同于磁盘加载程序。 |
| OpenSBI 在 M 态，内核在 S 态；SBI 输出使用 `ecall` | 特权级与受控服务入口：限制执行权限，通过陷阱请求更高权限的服务 | 本实验实际发生 S→M→S 的固件调用。通常讨论的用户系统调用是 U→S→U，本实验尚无用户程序、系统调用表和用户参数检查。S 态也可以在许可范围内直接操作设备，不能笼统说所有硬件访问都必须经过 SBI。 |
| 固件用 `mret` 进入内核；`ecall` 触发固件陷阱处理 | 异常与现场恢复：记录原因和返回位置，通过软件保存现场，再返回被中断的执行流 | 可以观察到 `mcause/mepc/mtvec` 等机制，但异常处理者是 OpenSBI。内核没有自己的时钟中断和页故障处理；不能说实验“完全没有异常”，也不能把已观察到的陷入说成内核已完成中断系统。 |
| `la sp,bootstacktop` 建立 8 KiB 启动栈，C 函数分配栈帧 | 执行上下文与栈：保存调用所需的数据、寄存器和返回位置 | 实验让调用约定与栈增长方向可见，但这里只设置一个启动栈。没有为每个进程建立独立内核栈，也没有上下文切换；不应把普通函数调用说成进程调度。 |
| `tail kern_init` 不建立新返回地址，函数末尾忙循环 | 控制流和启动入口约定：从低层入口交接到长期运行的内核代码 | `noreturn` 是编译器约定，实际不返回由循环保证；尾跳转不自动清理栈。忙循环仅让 CPU 持续执行同一位置，不是休眠、等待队列或空闲任务调度。 |
| `.text/.rodata/.data/.sdata` 排列，`[edata,end)` 清零 | 程序布局与运行时初始化：区分代码、只读数据、初始化数据和零初始化数据 | 本实验的链接地址与加载位置一致，入口 `satp=0`，未启用分页。段名和 ELF 标志描述组织及装载属性，不等于页表权限已生效；本次 `edata=end`，清零长度实际为零。 |
| `PGSIZE=4096` 与启动栈页对齐 | 内存管理的粒度：以页组织映射、分配和保护 | 本实验只使用页大小常量及对齐约束，尚未实现物理页描述符、分配器和页表。按 4 KiB 对齐是布局条件，不能作为已实现分页的证据。 |
| 源文件 → 目标文件 → ELF → 裸镜像，QEMU 加载 ELF | 编译、链接与装载：解析符号、确定地址，再建立可执行的内存内容 | 原理中的“程序装入”在这里表现为 ELF 程序头与入口字段，而非用户进程的 `exec`。链接器规定布局，QEMU 放置内核，OpenSBI 交接权限，三者职责不同。 |
| `cprintf` 的格式化回调与 SBI 字符输出 | 分层设计与设备抽象：上层表达操作，底层封装具体实现 | 格式化在 S 态完成，逐字符通过 SBI 交给 M 态固件访问 UART。内核没有缓冲队列、中断驱动发送或 DMA；这是一条最小输出通路，尚不是完整设备管理子系统。 |

这些关系说明，操作系统的抽象机制需要明确的硬件入口、地址布局与软件约定共同支撑。例如，“可以调用 C 函数”背后要求有效栈，“可以输出字符”背后需要陷阱和固件服务；它们都可以通过源码和寄存器值核对，而不只是概念上的流程箭头。

### 2. 原理中重要、但本实验尚未覆盖的知识点

| 未覆盖内容 | 原理中的作用 | 当前实验的边界 |
|---|---|---|
| 物理内存分配与回收 | 维护空闲页或内存块，满足动态分配请求并回收资源 | 栈是静态预留，没有页描述符、空闲链表、伙伴系统或动态内存分配器。 |
| 虚拟内存、页表、TLB 与缺页处理 | 建立地址空间隔离，支持映射、保护、按需分页与换页 | `kern_init` 不设置页表或开启地址转换；常量和页对齐不能代替映射管理。 |
| 进程／线程生命周期与调度 | 创建、运行、阻塞和退出执行实体，分配 CPU，保存恢复上下文 | 当前启动执行流没有 PCB、进程状态、调度队列或切换函数；末尾循环没有调度其他任务。 |
| 用户态程序与系统调用 | 在隔离的用户空间运行程序，通过内核接口访问受保护资源 | 没有 U 态程序加载、系统调用分发和用户指针验证；现有 SBI 是内核对固件的调用。 |
| 内核中断与异常处理 | 响应时钟、外设和页故障，保存现场、处理事件并恢复执行 | 固件已处理 SBI 陷阱，但当前内核没有建立自己的处理通路；`kbd_intr/serial_intr` 是空函数，不能据此说已有驱动中断处理。 |
| 同步、互斥与死锁处理 | 协调共享资源访问，避免竞争并处理等待依赖 | 当前输出和启动代码没有锁、信号量、条件变量或并发任务；本次单 hart 验证也没有检验多核并发。 |
| 文件系统与持久化 | 组织目录、文件、磁盘空间，提供读写、缓存和一致性机制 | 没有文件对象、目录、块分配或磁盘驱动；`ucore.img` 是裸内核镜像，不是已实现的文件系统。 |
| 完整设备管理和 I/O 调度 | 管理设备、缓冲、中断、DMA 及多请求的排队和完成 | `cons_init` 为空，字符输出依赖固件，内核没有实现完整设备注册与异步 I/O 管理。 |
| 进程间通信与网络 | 在执行实体之间传递数据，协调通信端点与协议状态 | 当前没有进程、管道、消息队列、套接字或协议栈。 |

“未覆盖”指这些功能没有由本次内核实现或验证，并不表示硬件或固件没有相应能力。特别是固件已提供陷阱和设备访问支持，后续实验需要在此基础上建立内核自己的管理机制。
