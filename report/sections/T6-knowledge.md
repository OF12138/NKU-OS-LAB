## 对操作系统的理解

### 本实验知识点与 OS 原理的对应

本实验主要完成物理内存的分配与回收。页分配器回答“哪些物理页可用、怎样分配”，页表回答“虚拟地址映射到哪里、允许怎样访问”，两者承担不同的职责。

| 实验中的实现 | 对应的 OS 原理 | 含义、关系与差异 |
| :--- | :--- | :--- |
| `page_init`、`struct Page` | 物理页帧管理与空闲空间管理 | 将物理内存按 4 KiB 页记录状态，保留 OpenSBI、内核和描述符数组占用的页，只把完整空闲页交给分配器。原理中的位图和空闲链表都是记录资源的方法；本实验用描述符数组保存更丰富的状态，且 `pages[i]` 对应物理页号 `nbase + i`，并非页号 `i`。 |
| First-Fit、Best-Fit | 连续分配、分裂合并与外部碎片 | First-Fit 找到首个足够大的空闲块，Best-Fit 选择足够大的最小块；本实验将这些策略用于连续物理页，粒度是页而非任意字节。两者都可能因空闲页不连续而分配失败；Best-Fit 的局部最小剩余量不保证长期碎片最少。释放时合并相邻空闲块，不能搬动已分配页来消除碎片。 |
| Buddy System | 按 2 的幂分级的伙伴分配 | 请求向上取整为 `2^k` 页，通过二分获得目标块，以“物理页号 XOR 块长”寻找伙伴。只有同阶、空闲的伙伴才能合并，地址相邻还不够。它简化了分裂和合并，但有内部碎片：申请 3 页实际占 4 页；分级管理也不保证任何连续页请求都能满足。 |
| SLUB、`kmalloc` / `kfree` | 内核小对象分配与对象缓存 | 在整页内划分定长对象，减少小对象直接占一整页的浪费。本实现提供 16～1024 字节的通用缓存，超过 1024 字节转交页分配器；页首元数据、对齐和大小档位仍有开销。它借鉴 SLUB 的空闲对象链和活动 slab，但每个 slab 固定一页，未实现多核缓存与 NUMA 管理。 |
| `entry.S`、`PADDR`、`page2pa` | 分页、地址转换与多级页表 | 启动页表在 Sv39 根表中用叶子项建立 1 GiB 大页映射，实际无需走满三级。`PADDR` 只对适用的内核线性映射做固定偏移换算；`page2pa` 则由描述符索引求物理页号，二者都不是通用页表查询。页分配粒度为 4 KiB，与这里的大页映射并不矛盾。 |
| QEMU 软件 TLB 调试 | 地址翻译缓存与页表更新同步 | TLB 缓存转换结果以减少页表遍历。QEMU 软件 TLB 还保存访问宿主机内存所需的信息，因此客户机处于 Bare 模式时仍使用它。实验观察的是 QEMU 4.1.1 的软件实现，不能据其表结构、容量或旧版本行为推断真实硬件；修改页表后的同步还需遵守 `sfence.vma` 的语义，详见分支任务。 |

### OS 原理中重要但本实验尚未实现的知识点

1. **按需分页与页面置换。** 本实验未建立“缺页后分配或换入页面”的处理流程，也没有 Clock、LRU、工作集或换入换出机制。物理页分配失败后，分配器不会自动从磁盘补充页面。
2. **进程地址空间与共享。** 尚无每进程页表、用户态访问隔离、写时复制和共享页反向映射。启动页表提供内核映射，`Page.ref` 字段本身不能构成这些机制。
3. **内存迁移与紧缩。** 合并空闲块只改变管理信息；紧缩则需迁移已占用页并更新相关映射。本实验没有实现紧缩，也未管理 NUMA 节点或内存热插拔。
4. **并发与其他 OS 子系统。** 分配器尚未提供多核并发访问所需的锁、原子操作和跨核 TLB 同步。进程调度、系统调用、文件系统和设备 I/O 管理也不属于本次实验的实现范围。
